Five steps, one of them yours

  1. Read the posting

    Greenhouse, Lever and Ashby postings come straight from their public APIs. Anything else is read from the page.

  2. Score the fit

    A 0–100 score with the skills you match and the ones you're missing, so you can skip a bad fit early.

  3. Tailor the documents

    Your real experience is reordered and reworded for this role. Degrees, certifications and contact details are never AI-written.

  4. Fill the form

    A real browser opens the application, uploads the PDFs and answers each question, noting where every answer came from.

  5. You approve

    Anything the assistant isn't sure about is highlighted. You check it, then it submits with exactly the answers you approved.

        Pre-flight checklist

        These rules are enforced in code, not left to the model's judgment.

        • No invented factsEducation, certifications and contact details are copied from your profile. The model can reword your experience but can't add to it.
          Documents
        • Blank beats a guessWork authorization, sponsorship and salary only come from answers you've set. If one isn't set, the field stays empty and gets flagged.
          Answers
        • Every answer shows its sourceEach field is labelled profile, saved answer, drafted or unknown, so you know which ones to read closely.

        How it's built

        Claude, with schemas

        Every model call uses structured outputs, so the code gets validated JSON back, never prose to parse.

        Playwright in a real browser

        Headed Chromium under Xvfb reads forms by their labels, which is why Greenhouse, Lever, Ashby and custom forms all use the same code.

        Python, Flask, SQLite

        One small database tracks each application from posting to offer. The dashboard and the worker hand jobs to each other through it.

        WeasyPrint

        Resumes and cover letters are HTML templates rendered to PDF, so any edit re-renders instantly with no model call.

        Self-hosted

        Docker containers on a home server behind Caddy. This public page reads a read-only copy of the data and can't reach anything else.

        Questions, answered

        What is ApplyPilot?

        ApplyPilot is an open-source AI job application assistant. Paste a job link and it reads the posting, scores your fit, tailors your resume and cover letter, and fills the employer's application form in a real browser. Then it stops and waits for you to review every answer.

        Does ApplyPilot submit job applications automatically?

        No. Filling is automatic, but submitting is not. Nothing is sent to an employer until you've reviewed the answers and approved them, and anything the assistant isn't sure about is flagged for you first.

        Which job application sites does it work with?

        Greenhouse, Lever and Ashby postings are read straight from their public APIs. Forms are filled by reading each field's label in a real Chromium browser, so it also handles many custom application forms.

        Will the AI make things up on my resume?

        No. Your experience can be reordered and reworded for the role, but nothing can be added to it. Education, certifications and contact details are copied from your profile, and questions like work authorization, sponsorship and salary are only answered from values you've set.

        What happens with CAPTCHAs and email verification codes?

        They go to you. ApplyPilot never tries to get around a CAPTCHA. It pauses the application and shows you the live page so you can finish that step yourself, and verification codes are typed in from the dashboard.

        Can I use ApplyPilot myself?

        The code is on GitHub under the MIT license. It's built to run on your own server with Docker and your own Claude API key. There's no hosted sign-up.
